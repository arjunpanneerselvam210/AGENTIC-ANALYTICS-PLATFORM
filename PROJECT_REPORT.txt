1. EXECUTIVE SUMMARY & OBJECTIVE
================================================================================
The Agentic Analytics Platform is an enterprise-grade, conversational business
intelligence system designed to run entirely on local computing infrastructure
without containerization overhead (No Docker). It empowers corporate stakeholders
from various divisions (Executive, Sales, HR, Finance, Inventory, Operations) to
interact with live corporate databases through natural language queries.

Key Differentiators Implemented:
- Dual-Database Isolation: Clean separation of business operations data (MySQL)
  from security and authentication metadata (PostgreSQL).
- Workforce vs. Application User Decoupling: Strict boundary between workforce
  personnel entities and system software logins.
- Authoritative Backend RBAC: AI models never dictate permissions; user identity
  and access rights are validated and injected strictly by the backend before
  query execution or LLM prompt construction.
- Local LLM Execution: Fully on-premise inference using Ollama with model
  specialization (llama3.1:8b for orchestrating and reasoning, qwen2.5-coder:7b
  for precision SQL generation).
- Fast, Secure APIs: Production-grade FastAPI backend with OAuth2/JWT and
  Bcrypt encryption.

3. DUAL-DATABASE ARCHITECTURE & DATA ISOLATION
================================================================================
A core architectural decision of this system is the complete separation of:

1. Business Operations Database (MySQL 8.0 - "company_analytics")
   - Contains all operational, transactional, and relational data across 5
     enterprise domains: HRMS, CRM, ERP/Inventory, Sales, and Finance.
   - Accessed exclusively in READ-ONLY mode by analytics queries and MCP tools.
   - Houses the workforce employee records (table: `employees`).

2. Authentication & Authorization Database (PostgreSQL 18 - "company_auth")
   - Contains user security credentials, bcrypt password hashes, role
     definitions, and granular permission mapping.
   - Houses the application logins (table: `users`).
   - Pure system administrators exist here without needing workforce profiles.
   - Enterprise operators (e.g. Sales Manager Arun Kumar) link to their
     corresponding workforce profile via `employee_id = 'E001'`.
